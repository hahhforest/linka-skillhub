# 产品流程与页面设计

状态：草案 2026-05-22

## 设计原则

`linka-skillhub` 是一个本地技能仓库控制台，不是宣传页。界面上只保留会改变状态、解释状态、帮助用户做决定的内容。任何不能点击、不能解释状态、不能推进流程的文案都不应该出现在主工作区。

默认运行在 `mirror` profile：读取真实 skills 的沙箱副本，写入沙箱 target。真实本机目录只在用户显式选择 `local` profile 后使用，并且所有写操作必须有确认。

## 核心对象

- Agent：技能来源或分发目标。包括 Mavis、OpenCode、Claude Code、Codex、`.agents/skills`。
- Skill：一个包含 `SKILL.md` 的目录包。
- Variant：同名 skill 的一个来源/内容版本，用内容 hash 区分。
- Registry：汇总仓库，保存原样 skill 包、manifest、审查记录和 prompt 版本。
- Review：对 skill 合法性、可迁移性、agent 绑定、风险的判断结果。
- Distribution Plan：从 registry 到目标 Agent 目录的复制/覆盖计划。

## 页面

### 1. 总览

目的：回答“当前选中范围内有什么 skills，它们处于什么状态”。

左侧 Agent 列表是筛选器：

- 未选择时显示全部来源。
- 点击某个 Agent 后，只显示该 Agent 的 skills，统计卡片、来源分布、状态分布、列表都随之变化。
- 再次点击取消筛选。

总览不做隐式扫描。页面显示最近一次扫描结果；如果没有扫描结果，显示空状态和“开始扫描”按钮。

最近扫描列表必须说明选择用途：选择 skill 是为了后续“审查”或“分发”。列表需要可滚动，不能只展示固定 5 条。

### 2. 扫描与审查

目的：让用户明确触发一次读取和判断，不静默调用本机 code agent。

扫描流程：

1. 用户点击“扫描 skills”。
2. 弹框显示将扫描的 profile、来源目录、是否包含 builtin/system。
3. 用户确认后才执行扫描。
4. 完成后更新总览和列表。

审查流程：

1. 用户选中一个或多个 skill，或选择“审查全部可见 skills”。
2. 点击“运行审查”。
3. 弹框列出可用审查器：规则审查、Codex、Claude Code、OpenCode、Mavis。
4. 用户选择审查器。没有可用 code agent 时，弹框说明原因并建议安装或使用规则审查。
5. 用户点击“开始审查”后执行。
6. 结果必须用当前 UI 语言输出，并写入 registry review 文件。

“规则审查”文案应解释为：不调用 LLM，只用确定性规则检查 YAML、名称、路径、敏感信息和 agent 绑定线索。

### 3. 仓库管理

目的：管理 registry 的导入、Git 状态和远端同步。

按钮文案必须使用动词 + 对象：

- “导入到 Registry”：把当前扫描到的 skills 原样复制到 registry，并更新 `registry/skills.json`。
- “运行规则审查”：对 registry 中的 skills 生成 review 记录，不调用 code agent。
- “推送到 GitHub”：提交 registry 变更并推送到远端。

每个按钮下方显示一句解释和影响范围。操作完成后显示清晰结果，例如“已导入 105 个 skill 包，跳过 4 个默认排除来源”。

### 4. 分发管理

目的：把 registry 中选中的 skill 分发到用户选择的目标 Agent 目录。

流程：

1. 用户选择 skill。
2. 用户选择一个或多个目标 Agent。
3. 点击“生成分发计划”。
4. 页面显示 copy / overwrite / skip 明细和备份目录。
5. 用户点击“执行分发”后才写入 target。
6. local profile 下执行写入必须二次确认。

分发计划必须由服务端根据当前 profile 重新生成，不能信任前端传入的可执行 path。

### 5. 技能详情

目的：解释一个 skill 为什么处于当前状态，以及它能不能共享。

详情页需要展示：

- frontmatter 摘要。
- 来源 Agent、scope、源路径、variant hash。
- 状态：合法、可共享、仅限 Agent、存在风险、无效。
- 证据：具体规则命中、YAML 错误、agent-bound 线索、敏感信息线索。
- 可执行动作：运行审查、加入分发选择、打开 registry 包路径。

### 6. 设置

右下角“设置”不能跳到仓库管理。设置是独立弹框或独立页，内容包括语言、profile、registry 路径、是否包含 builtin/system、默认审查器。没有实现前不要放设置按钮。

## 多语言

默认中文，可在顶部 banner 切换英文。

UI 文案必须来自统一字典，不在组件里散写。审查 prompt 也分中文和英文两份：

- 中文 UI -> 默认使用中文审查 prompt，审查摘要和建议输出中文。
- 英文 UI -> 默认使用英文审查 prompt。

## 状态口径

统计必须基于当前筛选范围，并且一个 skill 只进入一个主状态桶：

1. 存在问题：invalid 或 unsafe。
2. 仅限 Agent：agent_bound，且不属于存在问题。
3. 可共享：valid + portable，且不是存在问题和仅限 Agent。
4. 待审查/其他：其余状态。

总数等于四个主状态桶之和。
